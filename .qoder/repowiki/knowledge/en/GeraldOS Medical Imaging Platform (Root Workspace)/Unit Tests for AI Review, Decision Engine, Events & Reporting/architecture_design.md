Tests are organized as one file per source module under `__tests__/lib/`, mirroring the production layout (`ai-review.test.ts`, `decision-engine.test.ts`, `events.test.ts`, `reporting.test.ts`). Each test file imports the target module via the `@/` path alias (e.g. `@/lib/ai-review`, `@/lib/decision-engine`) and groups assertions with nested `describe` blocks keyed by exported function or constant name. External dependencies — the database client (`@/db`), audit logger (`@/lib/audit`), event publisher (`@/lib/events`), Redis (`ioredis`), and integration config (`@/lib/integrations`) — are isolated using Vitest's `vi.mock` at the top of each file so tests run without a live DB, Redis, or external services. Assertions focus on invariants such as modality coverage, score ranges, status enums, and safety boundaries (e.g. no auto-acceptance of findings, no autonomous diagnosis).
