Built on Next.js App Router with a clear separation between server routes under `src/app/api/` (one folder per domain — auth, patients, appointments, orthanc, reports, ai-review, agents, etc.) and page routes under `src/app/` that render feature pages. The root layout (`src/app/layout.tsx`) wraps every route in `Providers` (React Query client) and `AppShellProvider`, then renders the global `CommandPalette`. UI is split into shared `components/ui/` primitives (shadcn-style button, card, dialog, table, tabs), layout components (`header`, `sidebar`, `shell`), and a dedicated `workstation/` subdirectory of rich panels (viewer, clinical, activity, report editor, worklist, context menu). Business logic lives in `src/lib/` as domain modules (`agents`, `ai-review`, `audit`, `decision-engine`, `events`, `finance`, `knowledge`, `reporting`, `workflow`, `hanging-protocols`, plus an `auth/` subfolder for OIDC/session handling). Data access is centralized through `src/db/index.ts` (Drizzle ORM client) and `src/db/schema.ts`, which defines the full PostgreSQL schema (patients, appointments, equipment, staff, workflow studies, invoices, payments, insurance claims, knowledge documents, AI observations/recommendations, bookmarks, annotations, event log, notifications). A `proxy.ts` at the module root likely forwards requests to external systems (Orthanc/DICOM, FHIR, n8n, MinIO). Dependency direction is strictly: pages → components → lib modules → db; API routes call lib modules directly without touching React components.
